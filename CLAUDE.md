## Workspace & Repositories

This repo is one of three **independent Git repositories** that live side by side in the parent `WorkoutTracker/` folder (the parent folder itself is not a repo):

| Folder | Repo | Stack | Hosting |
|--------|------|-------|---------|
| `workout_tracker/` (this repo, a.k.a. WorkoutTrackerMobile) | Flutter mobile app | Flutter / Dart | Android & iOS builds |
| `WorkoutTrackerAPI/` | Backend | .NET (ASP.NET Core controllers, EF Core) | Railway |
| `Workout_tracker_admin/` | Admin panel | React / Vite | Vercel |

- Only modify the repository you were asked to work on. Touch another repo only when explicitly requested (e.g. a genuine API incompatibility → report it, don't change the backend on your own).
- Never commit or push unless explicitly asked.
- The mobile app talks to the backend only over HTTP; the backend's controllers (`WorkoutTrackerAPI/Controllers/`) are the source of truth for request/response shapes.

## Commands

```bash
# Run the app (Android emulator or device)
flutter run

# Point at a different backend (default is the Railway production URL)
flutter run --dart-define=API_BASE_URL=http://<host>:<port>

# Build release APK
flutter build apk --release

# Run all tests
flutter test

# Run a single test file
flutter test test/some_test.dart

# Regenerate Hive type adapters after editing @HiveType/@HiveField models
flutter pub run build_runner build --delete-conflicting-outputs

# Analyze for lint errors
flutter analyze

# Get dependencies
flutter pub get
```

## Architecture

**State Management:** Provider (`ChangeNotifier` / `ChangeNotifierProvider`). App-wide ViewModels are registered in `main.dart`'s `MultiProvider`; widgets call `context.watch<VM>()` or `context.read<VM>()`. Self-contained one-off screens (e.g. `AddFriendPage`, the bug-report pages) are `StatefulWidget`s that take an injectable service instead of a global ViewModel.

**Backend:** The .NET WorkoutTrackerAPI, deployed on Railway.
- `lib/core/api/api_config.dart` — base URL (`API_BASE_URL` dart-define, defaulting to the Railway production URL) and timeouts.
- `lib/core/api/api_client.dart` — `ApiClient.instance`, a Dio singleton. Attaches `Authorization: Bearer <jwt>`, refreshes the token once on a 401 (`/api/auth/refresh`, queued so concurrent 401s refresh once), clears the token when refresh fails, and maps every failure to an `ApiError` with a `NetworkReason` (`noConnection`, `timeout`, `serverError`, `unauthorized`, `requestFailed`, `unknown`). Public methods never throw.
- `lib/core/api/api_result.dart` — sealed `ApiResult<T>` = `ApiSuccess` | `ApiError`.
- Feature services (`*_api_service.dart`, `friendsService.dart`, `leaderboard_service.dart`, `accountReposirtry.dart`, …) wrap `ApiClient` calls; most convert an `ApiError` into a thrown exception for their callers.
- `docs/backend-contracts.md` — contracts written for specific features (password reset, sex/date-of-birth profile fields).

**Auth:** `lib/core/auth_token.dart` — `AuthToken.I` holds the JWT (persisted in `flutter_secure_storage` under `jwt_token`; user id decoded from the `sub` claim). `AuthToken.I.load()` runs in `main()` before `runApp`. `lib/core/pb.dart` is a leftover compatibility shim from the old PocketBase backend (only `clearAuthEverywhere()` → `AuthToken.I.clear()`); don't add to it.

**Local Storage:** Hive for all offline-first data. All Hive boxes are opened in `main()` before `runApp`. Models that persist to Hive have a `.g.dart` file generated by `build_runner`. After editing any `@HiveType` class, regenerate adapters.

|--------|-------|

| 2 | PerformedSet |
| 3 | ExerciseLog |
| 4 | WorkoutHistoryEntry |
| 5 | PlannedSet |
| 30 | MeasurementEntry |

| 50 | DurationAdapter (manual) |
| 77 | ExerciseNote |

**Sync:** Local Hive data is pushed to / reconciled with the backend by feature services (e.g. `workout_history_reconciler.dart`, `synced_sessions_store.dart`, `pending_*_deletes_store.dart`). `lib/core/services/` holds the shared pieces: `NetworkReconnectNotifier` (connectivity_plus, fires on offline→online), `ReconnectSyncBinder`, `SyncCoordinator`, `LocalDataGuard` (prevents one account's cached data leaking into another's), `DeepLinkService` (`workouttracker://reset-password?token=…`).

**Online/Offline mode:** `AppManager` (Provider) holds a `SessionMode` enum. The `Account` tab only appears in the bottom nav when `AppManager.isOnline == true`. Offline users have full access to templates, session tracking, history, and measurements without an account; account-only features (profile, friends, leaderboards, bug reports) are reached from the Account tab.

**App version:** `DeviceContext.init()` (`lib/home/support/services/device_context.dart`) reads the build's version via `package_info_plus` in `main()`; `DeviceContext.appVersion` (`version+build`, from pubspec `version:`) is shown in the Account footer and attached to bug reports. Don't hard-code version strings.

## Key Patterns

**Repository pattern:** Hive-backed features have an abstract `XRepository` interface and a `HiveXRepository` implementation; ViewModels depend on the interface.

**Testable services:** API services are plain, non-`final` classes so tests can subclass them and override individual methods (e.g. `FakeApi extends WorkoutSessionsApiService`, `FakeBugReportApi extends BugReportApiService`). Pages take the service as an optional constructor argument.

**Session flow:** `TemplatesPage` → `ViewTemplatePage` → `StartSessionFlow` (in `templates/navigation/`) pushes `StartSessionPage`, which creates a scoped `WorkoutSessionViewModel` via `ChangeNotifierProvider`. On finish, the entry is saved through `HistoryViewModel.save()`.

**PR detection:** Happens inside `WorkoutSessionViewModel.markPlannedSetDone()` using `WorkoutSessionPrService`. PRs are stored separately in `prEventsBox`.

**Streak:** Server-owned — read from `AccountViewModel` (backed by `/api/users/me`). `StreakCalculator.compute()` in `lib/home/account/model/streakCalculator.dart` is a pure helper.

**Exercise catalog:** Built-in exercises are a hardcoded static list in `exerciesesList.dart`, referenced by integer `id`; user-created ones live in `CustomExercisesRepository`. Category icons live in `assets/workout_category/` (with `male/` and `female/` variants).

**Bug reports (`home/support/`):** `BugReportApiService` → `POST /api/bug-reports` (multipart: `title`, `description`, `appVersion`, `platform`, `deviceInfo`, `appScreen`, optional `screenshot` file with an explicit image content type), `GET /api/bug-reports/mine`, `GET /api/bug-reports/mine/{id}`. Failures are thrown as `BugReportApiException` carrying the `NetworkReason`. `ScreenshotValidator` mirrors the backend's JPEG/PNG/WebP + 5MB rules. Priority and status are server-owned and display-only; admin notes never reach the client.

## Adding a New Hive Model

1. Define the class with `@HiveType(typeId: N)` — pick a typeId not in the table above.
2. Run `flutter pub run build_runner build --delete-conflicting-outputs`.
3. Register the adapter in `main()` with `Hive.registerAdapter(YourModelAdapter())`.
4. Open the box with `await Hive.openBox<YourModel>('yourBoxName')`.
